# UI Revamp Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** ship the designed theme everywhere and add a status window that shows live tunnel state, per `docs/superpowers/specs/2026-08-13-ui-revamp-design.md`.

**Architecture:** two new leaf packages with no fyne-widget dependencies in their logic (`internal/uitheme`, `internal/uistate`), one new window package (`internal/status`), and wiring in `cmd/openfortitray`. `internal/tray` loses its private `view` type and consumes `uistate` instead, so the tray and the window can never disagree about state.

**Tech Stack:** Go, fyne v2.8.0 (`fyne.Theme`, `canvas`, `container`, `widget`), fyne's `test` package for headless tests.

## Global Constraints

- Token values are the spec's tables **verbatim**. Every token defined for BOTH variants; the theme test asserts this.
- Sizes: Text 13, CaptionText 11, SubHeadingText 15, HeadingText 20, Padding 5, InnerPadding 10, CardRadius 8, ButtonRadius 6, InputRadius 6, SeparatorThickness 1.
- No embedded font. fyne 2.8 already bundles Inter; `Font()` delegates to the default theme.
- State colour (`Success`/`Warning`/`Error`) appears ONLY in the status dot and the settings status strip. Never as an accent.
- No animation, no per-frame relayout: Mesa llvmpipe is a shipping target. The 1 Hz uptime tick is the fastest thing on screen.
- No traffic counters. The "Sent / Received" row is out of scope (no data source).
- Every existing test keeps passing. `go test ./... -race` is the gate.
- Accent is `#2F6FEB` / `#5B93F5`. The status window is hidden at startup and opened from the tray, plus once on first run.

### Task 2: `internal/uistate`

**Files:**
- Create: `internal/uistate/uistate.go`
- Test: `internal/uistate/uistate_test.go`

**Interfaces:**
- Produces:
  ```go
  type Kind int // KindIdle, KindBusy, KindOK, KindBad
  type View struct {
      State         tunnel.State
      Kind          Kind    // drives the dot colour
      Title         string  // "Connected", "Reconnecting", …
      Detail        string  // short, already truncated
      MenuLabel     string  // what the tray status row shows (title + detail)
      AssignedIP    string  // "" unless Connected
      CanConnect    bool
      CanDisconnect bool
  }
  func ViewFor(e tunnel.Event) View
  type Ring struct{ … }
  func NewRing(n int) *Ring
  func (r *Ring) Add(e tunnel.Event, at time.Time)
  func (r *Ring) Entries() []Entry // newest first
  type Entry struct{ At time.Time; Text string }
  ```

**Design:** `ViewFor` is the current `tray.viewFor` logic, widened. `MenuLabel` reproduces today's tray label exactly (`"Connected — 10.0.0.88"`, `"Reconnecting — …"`, `"Error: …"`) so Task 3 is behaviour-preserving. `Ring` is a fixed-size slice with a head index; `Add` drops an event whose `(State, Detail)` equals the newest entry's, so a reconnect storm does not flood the list. `CanDisconnect` is not always `!CanConnect` — both are false in `Authenticating`, where Cancel is a distinct action; the tray keeps using `CanConnect` for its two items, which preserves today's behaviour.

- [ ] **Step 1: Write the failing test** — a table over all six `tunnel.State` values plus the detail-truncation cases (>60 runes truncated with `…`, CR/LF cut at the first line break), asserting every `View` field. Plus `Ring` tests: capacity eviction, newest-first order, duplicate suppression.
- [ ] **Step 2:** `go test ./internal/uistate/` — FAIL.
- [ ] **Step 3: Implement.** Move `short`/`maxDetail` here.
- [ ] **Step 4:** `go test ./internal/uistate/ -race` — PASS.
- [ ] **Step 5: Commit** `feat(ui): shared view model for the tray and the status window`

### Task 4: `internal/status` — the window

**Files:**
- Create: `internal/status/status.go`
- Test: `internal/status/status_test.go`

**Interfaces:**
- Consumes: `uistate.View`, `uistate.Ring`, `tunnel.Event`, `config.Config`
- Produces:
  ```go
  type Host interface {
      Connect(); Disconnect()
      ShowSettings()
      LogPath() string
      GatewayLabel() string // "vpn.example.com:10443" for the active profile
      DTLSLabel() string    // "DTLS on" | "DTLS off"
  }
  func New(host Host, win fyne.Window) *Controller
  func (c *Controller) Show()
  func (c *Controller) Apply(e tunnel.Event)
  func (c *Controller) Tick() // 1 Hz uptime refresh; no-op unless Connected and visible
  ```

**Design:** the widget tree from the spec — header (`canvas.Circle` + two labels), detail card (`widget.Card`-free: a `container.NewVBox` of rows on a `canvas.Rectangle` in `HeaderBackground` with `CardRadius`), button row, and a collapsible activity list. `Apply` mutates existing widgets and calls `Refresh` on each — never rebuilds the tree, so llvmpipe is not asked to relayout. `win.SetCloseIntercept(c.win.Hide)`, matching Settings.

Uptime: `Apply` records `connectedAt` on the first `Connected` event and clears it on any non-connected state. `Tick` recomputes only the uptime label.

- [ ] **Step 1: Write the failing test** using `test.NewApp()`:
  - `TestApplyRendersEachState`: feed one event per state, assert the state label, the detail label, the dot's colour token, and which button is enabled/what its label is.
  - `TestCloseHidesRatherThanQuits`: the close intercept is set and calling it leaves the app running.
  - `TestConnectButtonDrivesHost` / `TestDisconnectButtonDrivesHost`: click via `test.Tap`, assert on a fake `Host`.
  - `TestUptimeTicks`: Apply a `Connected` event, advance an injected clock, `Tick()`, assert the label changed; assert `Tick()` on a disconnected window is a no-op.
  - `TestActivityListShowsNewestFirst`.
- [ ] **Step 2:** `go test ./internal/status/` — FAIL.
- [ ] **Step 3: Implement.** Inject the clock as a `now func() time.Time` field defaulting to `time.Now`.
- [ ] **Step 4:** `go test ./internal/status/ -race` — PASS.
